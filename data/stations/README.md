# ผังสถานี (`data/stations/<id>.json`)

ไฟล์ละ 1 สถานี ชื่อไฟล์ต้องตรงกับ `id` เกมอ่านทุกไฟล์ในโฟลเดอร์นี้ตอน build (ไม่มีการดึงข้อมูลตอนเล่น)
ทุกไฟล์ต้องผ่านตัวตรวจ `validateStation` (รัน `npm run test:sim`) ไฟล์ที่ไม่ผ่านจะถูกข้าม ด่านที่ใช้ผังนั้นถูกปิด เกมส่วนอื่นยังเล่นได้ ข้อความ error บอกตำแหน่งในไฟล์และวิธีแก้

- **สถานีจริงและผังใหม่ทุกผังใช้ schema 2** (รางสองทิศ หลายขา ทางตัน) เอกสารนี้อธิบาย schema 2 เป็นหลัก
- schema 1 คือผังทิศเดียวของ 12 ด่านโหมดประวัติศาสตร์ (`fictional-history-*.json`) ยังโหลดได้ ดูภาคผนวกท้ายไฟล์
- ไฟล์ที่ขึ้นต้นด้วย `fictional-` และมี `"fictional": true` เป็นผังสมมุติ ทีมวาดเอง ไม่มีข้อมูลจาก OpenStreetMap
- สถานีจริง (`"fictional": false`) ต้องมี `sources` อย่างน้อย 1 รายการ และทำตาม `docs/DATA-PIPELINE.md`

ตัวอย่างที่ใช้ได้จริง (ผ่านตัวตรวจและมีบอทเล่นผ่าน): `fictional-crossing-1-loop.json` (ทางเดี่ยว 1 ทางหลีก), `fictional-terminus-2-tracks.json` (ปลายทาง 2 ทางตัน), `fictional-junction-3-legs.json` (ชุมทาง 3 ขา)

## schema 2 ในหน้าเดียว

```json
{
  "schema": 2,
  "id": "tha-kilen",
  "fictional": false,
  "upDir": "E",
  "name_th": "ท่ากิเลน", "name_en": "Tha Kilen",
  "verified": { "layout": false, "signalling": false, "notes": "" },
  "sources": [{ "osm": "https://www.openstreetmap.org/node/…", "fetched": "2026-10-12" }],
  "layout": {
    "size": [960, 480],
    "tracks": {
      "bw": { "pts": [[-100, 300], [150, 300]] },
      "ap": { "pts": [[150, 300], [190, 300]] },
      "b":  { "pts": [[190, 300], [260, 210], [360, 210]] },
      "c":  { "pts": [[190, 300], [360, 300]] },
      "k1": { "pts": [[360, 210], [640, 210]] },
      "k2": { "pts": [[360, 300], [640, 300]] },
      "x1": { "pts": [[640, 210], [740, 210], [810, 300]] },
      "x2": { "pts": [[640, 300], [810, 300]] },
      "bp": { "pts": [[810, 300], [850, 300]] },
      "be": { "pts": [[850, 300], [1070, 300]] }
    },
    "points": {
      "P1": { "x": 190, "y": 300, "N": "c",  "R": "b" },
      "P2": { "x": 810, "y": 300, "N": "x2", "R": "x1" }
    },
    "signals": {
      "S1": { "track": "bw", "dir": "E", "type": "home" },
      "S2": { "track": "be", "dir": "W", "type": "home" },
      "T1": { "track": "k1", "dir": "E", "type": "starter" },
      "T2": { "track": "k2", "dir": "E", "type": "starter" },
      "U1": { "track": "k1", "dir": "W", "type": "starter" },
      "U2": { "track": "k2", "dir": "W", "type": "starter" }
    },
    "platforms": [{ "track": "k1", "no": 1 }, { "track": "k2", "no": 2 }],
    "roles": { "main": "k2", "loop1": "k1" },
    "portals": {
      "W": { "track": "bw", "label_th": "ไปหนองปลาดุก" },
      "E": { "track": "be", "label_th": "ไปน้ำตก" }
    }
  }
}
```

### ส่วนหัว
| ฟิลด์ | ความหมาย |
|---|---|
| `schema` | `2` |
| `id` | ตัวพิมพ์เล็ก ตัวเลข ขีดกลาง ตรงกับชื่อไฟล์ |
| `fictional` | `true` = ผังสมมุติ, `false` = อ้างอิงสถานีจริง |
| `upDir` | `"E"` หรือ `"W"`: ทิศบนแผงที่เป็น **เที่ยวขึ้น** (วิ่งออกจากกรุงเทพ) เกมใช้แปลงทิศเป็นคำว่าเที่ยวขึ้น/เที่ยวล่องตอนแสดงผลเท่านั้น ตรรกะทั้งหมดใช้ E/W |
| `verified`, `sources` | ตาม `docs/DATA-PIPELINE.md` ข้อ 4 (ผังสมมุติใส่ `sources: []`) |
| `layout.size` | ขนาดแผง `[กว้าง, สูง]` ไม่ใส่ = `[960, 480]` รางที่เลยขอบแผงออกไป (เช่น x = −100 หรือ 1070) คือส่วนที่รถวิ่งเข้า/ออกจอ |

### `layout.tracks` รางกายภาพ
- ราง 1 เส้น = polyline `pts` อย่างน้อย 2 จุด **วิ่งได้สองทิศเสมอ** ไม่ต้องเขียนแยกทิศ
- **เขียนจุดจากซ้ายไปขวา** (x ของจุดแรกน้อยกว่าจุดสุดท้าย) ทิศ `E` = วิ่งตามลำดับจุด, ทิศ `W` = วิ่งย้อน
- **รางต่อกันเมื่อพิกัดปลายตรงกันพอดี** ไม่ต้องเขียน `next` ปลายขวาของรางหนึ่งต่อกับปลายซ้ายของรางถัดไป
- ที่จุดต่อ 1 จุด มีได้แค่ 2 แบบ: ราง 2 เส้นต่อกัน หรือราง 3 เส้น (ประแจ: 1 เส้นด้านหนึ่ง 2 เส้นอีกด้าน ต้องประกาศใน `points`)
- แบ่งรางเป็นท่อนตรงที่ต้องการ: (1) จุดต่อและประแจ (2) ปลายทางจอด (3) ตำแหน่งสัญญาณ เพราะสัญญาณอยู่ที่ปลายรางเท่านั้น
- `"berth": true` (ไม่บังคับ): รางรอที่ไม่ใช่ทางจอดแต่มีสัญญาณหัวท้าย ให้นับเป็นตอนของตัวเอง ไม่รวมกับคอสถานี
- ชื่อรางใช้ a–z A–Z 0–9 `_` `-` (ภายในเกมขอบรางทิศ W ของราง `k1` ชื่อ `k1~`)

### `layout.points` ประแจ
`{ "x", "y", "N": รางทางตรง, "R": รางทางแยก }` ตำแหน่งต้องตรงกับจุดที่ราง 3 เส้นบรรจบ `N` และ `R` คือรางสองเส้นที่อยู่ด้านเดียวกัน รางเส้นที่สามเป็นโคนประแจ (เอนจินหาเอง) ประแจตัวเดียวเป็นประแจสวนสำหรับทิศหนึ่งและประแจตามสำหรับอีกทิศโดยอัตโนมัติ รถที่เข้าทางขาที่ประแจไม่ได้ตั้งไว้ = รถฝ่าประแจ

### `layout.signals` สัญญาณ (เสาเข้า เสาออก)
- `track` + `dir`: เสาตั้งอยู่ **ปลายรางด้านที่รถทิศ `dir` วิ่งไปถึง** (ทิศ `E` = ปลายขวา, ทิศ `W` = ปลายซ้าย) และบังคับเฉพาะขบวนทิศนั้น ขบวนทิศตรงข้ามไม่สนใจ
- รางหนึ่งเส้นมีเสาได้ทิศละ 1 ต้น
- `type`: `"home"` (เสาเข้า), `"starter"` (เสาออก) ใช้กับตัววาดและข้อความ
- `label` (ไม่บังคับ): ชื่อที่ผู้เล่นเห็น แยกจาก id ภายใน (ไม่ใส่ = ใช้ id) เปลี่ยนชื่อเสาได้โดยไม่กระทบตารางเส้นทาง
- `lx`, `ly` (ไม่บังคับ): ตำแหน่งเสาบนแผง ไม่ใส่ = เอนจินวางให้ทางซ้ายมือคนขับ (ทิศ E อยู่เหนือราง ทิศ W อยู่ใต้ราง)
- เส้นทางของเสาแต่ละต้นเอนจินคำนวณเอง: จากเสานั้นไปจนถึงรางถัดไปที่มีเสาทิศเดียวกัน ขาออก หรือทางตัน

### `layout.platforms` ทางจอด และ `layout.roles` บทบาททาง
- `platforms`: `{ "track", "no", "noPlatform"? }` ทางที่ขบวนจอดได้ ข้อความในเกมเรียกว่า "ทาง n" ใส่ `"noPlatform": true` ถ้าทางนั้นไม่มีชานชาลา (คำใบ้ทางสำรองจะเสนอทางนี้ให้ขบวนโดยสารเป็นลำดับท้าย) `no` คือเลขทางที่ผู้เล่นเห็น (กำหนดสีขบวนด้วย) ทางจอดต้องยาวอย่างน้อย 84 (ขบวนยาว 72 + ระยะหยุด 6 สองด้าน) และต้องมีเสาออกทุกทิศที่ไม่ใช่ทางตัน
- `roles`: `{ "ชื่อบทบาท": "ชื่อราง" }` ตารางขบวนในภารกิจอ้างทางด้วยชื่อบทบาท ผังเปลี่ยนชื่อรางได้โดยภารกิจไม่ต้องแก้ ชื่อที่ภารกิจสายน้ำตกใช้: `main` (ทางประธาน), `loop1`, `loop2` (ทางหลีก), `bay1` (ทางตัน), `t1`–`t3` (ทางจอดที่ชุมทาง) รางที่มีบทบาทต้องอยู่ใน `platforms`

### `layout.portals` ขาเข้าออก และ `layout.buffers` ทางตัน
- ปลายรางที่ไม่ต่อกับอะไรต้องประกาศเป็นอย่างใดอย่างหนึ่ง ไม่งั้นตัวตรวจตีกลับ (กันพิกัดพิมพ์ผิด)
- `portals`: `{ "ชื่อขา": { "track": รางที่ปลายลอยออกนอกผัง } }` ชื่อขาคือสิ่งที่ตารางขบวนใช้ใน `from` / `to` สถานีสองด้านใช้ `W` / `E` ชุมทางใช้ `A` / `B` / `C`
  - `label_th`: ชื่อที่ผู้เล่นเห็น เช่น "ไปน้ำตก"; `neighbor`: id สถานีข้างเคียง (เผื่อแผนที่)
  - `dir`: `"both"` (ค่าเริ่มต้น), `"in"` รับเข้าอย่างเดียว, `"out"` ออกอย่างเดียว ใช้ทำทางคู่: ขาละ 2 ราง รางหนึ่ง `in` อีกรางหนึ่ง `out`
  - `runTime` (ค่าเริ่มต้น 8): วินาทีที่ขบวนใช้วิ่งในตอนระหว่างสถานีฝั่งนั้น; `block: false` ปิดกติกาตอนทางเดี่ยวของขานี้
  - ขาที่รถเข้าได้ **ต้องมีเสาเข้าบนรางของขานั้น** (ทิศเข้าหาสถานี) รางของขาจึงเป็นรางช่วงก่อนถึงเสาเข้า และใช้เป็นทางจอดไม่ได้
- `buffers`: `["ชื่อราง", …]` รางที่ปลายลอยเป็นกันชน (ทางตัน) ขบวนหยุดก่อนถึงปลาย 6 หน่วย

## แบบแผนที่ใช้บ่อย

**ทางเดี่ยว + ทางหลีก (ท่ากิเลน, วังโพ):** ตัวอย่างข้างบน ลำดับจากซ้าย: รางขา → รางสั้นก่อนประแจ → ประแจ → รางเชื่อมสองขา → ทางจอด → รางเชื่อม → ประแจ → รางสั้น → รางขา วังโพ (3 ทาง) เพิ่มประแจอีกตัวต่อฝั่งและทางจอดอีกเส้น

**ทางตัน / สถานีปลายทาง (น้ำตก, ทางตันที่กาญจนบุรี):**
```json
"tracks": { "…": {}, "k1": { "pts": [[360, 210], [700, 210]] } },
"signals": { "U1": { "track": "k1", "dir": "W", "type": "starter" } },
"platforms": [{ "track": "k1", "no": 1 }],
"buffers": ["k1"]
```
ทางตันมีเสาออกด้านเดียว (ด้านที่ต่อกับสถานี) ขบวนเข้าไปจอดจนครบเวลาแล้ว **กลับหัวเองทั้งขบวน** เมื่อขาออกที่ต้องไปอยู่ด้านหลัง (ตารางขบวน `from` = `to` ใช้กับทางจอดธรรมดาได้ด้วย) สถานีปลายทางมี `portals` ขาเดียว

**ชุมทางหลายขา (หนองปลาดุก):** ใส่ประแจแยกหลังรางสั้นของคอสถานี แล้วให้แต่ละขามีรางคั่น 1 เส้นก่อนรางของขา (เพื่อให้เสาเข้าไม่ล้ำหลักเขตปลอดภัย)
```json
"tracks": { "bp": { "pts": [[810, 300], [850, 300]] },
            "ea": { "pts": [[850, 300], [900, 300]] }, "eb": { "pts": [[850, 300], [910, 360]] },
            "pa": { "pts": [[900, 300], [1070, 300]] }, "pb": { "pts": [[910, 360], [1070, 360]] } },
"points": { "P3": { "x": 850, "y": 300, "N": "ea", "R": "eb" } },
"signals": { "SB": { "track": "pa", "dir": "W", "type": "home" }, "SC": { "track": "pb", "dir": "W", "type": "home" } },
"portals": { "B": { "track": "pa" }, "C": { "track": "pb" } }
```
เสาออกที่ไปได้หลายขามีหลายเส้นทาง ผู้เล่นเลือกด้วยประแจ (หรือแตะป้ายขาในยุคแผงต้นทาง-ปลายทาง)

## สิ่งที่ตัวตรวจจับให้ (ไม่ต้องตรวจมือ)
- ปลายรางลอยที่ไม่ได้ประกาศ, ราง 3 เส้นบรรจบที่ไม่มีประแจ, ราง 4 เส้นขึ้นไปบรรจบ, รางที่เขียนขวาไปซ้าย, รางที่ไปไม่ถึงจากขาเข้า
- ทางจอดสั้นกว่าขบวน, ทางจอดไม่มีเสาออก, ขาเข้าไม่มีเสาเข้า, เสาซ้ำ, เสาหันออกนอกผังหรือเข้าหาทางตัน
- **เสาล้ำหลักเขตปลอดภัย:** ถ้ารางที่มีเสาต่อเข้าประแจโดยตรงทางขาแยก ขบวนที่จอดหน้าเสาจะห่างรางอีกขาไม่ถึง 24 หน่วย ให้คั่นด้วยรางสั้นอีกเส้น (เช่น `x1`, `x2` ในตัวอย่าง)
- บทบาททางชี้รางที่ไม่ใช่ทางจอด, ขาชี้รางที่ไม่มีปลายลอย

## สิ่งที่เกมคำนวณเอง (ไม่ต้องเขียนในไฟล์)
- ตารางเส้นทางของเสาทุกต้น (ไปถึงไหน ต้องตั้งประแจอะไร) และตารางขัดกัน
- **ตอนราง:** ทางจอด รางของขา และทางตัน เป็นตอนของตัวเอง รางที่เหลือที่ต่อถึงกันรวมเป็น "คอสถานี" ฝั่งละ 1 ตอน
- **overlap (ทางหยุดเลย):** เส้นทางรับเข้าทางจอดจองรางและประแจบนทางที่ขบวนจะไปถ้าหยุดเลยเสาออก คือเดินต่อจากเสาออกตามท่าประแจที่เป็นอยู่จนถึงรางของขา (ไม่ใช่ทั้งคอสถานี) จนขบวนจอดนิ่งครบ 2 วินาที เส้นทางอื่นที่ใช้รางบนทางนั้นตั้งไม่ได้ และ overlap สองอันในคอสถานีเดียวกันขัดกันเสมอ (กติกา "ในเกมนี้รับขบวนเข้าทีละขบวน") ทางตันไม่ต้องมี overlap
- **ตอนทางเดี่ยว:** ขาละ 1 ตอน มีขบวนได้ทีละขบวน ขบวนที่รอหน้าเสาเข้ายังครองตอน เสาออกเปิดไม่ได้ถ้าตอนไม่ว่าง

## ข้อจำกัดของเอนจินตอนนี้ (ถ้าผังจริงมีสิ่งเหล่านี้ ให้ย่อผังหรือแจ้ง engine-dev)
- ไม่มีทางตัด (diamond) ประแจคู่ (double slip) หรือประแจ 3 ทาง: จุดต่อ 1 จุดมีรางได้ไม่เกิน 3 เส้น ทางเชื่อมทแยง (crossover) ทำได้ด้วยประแจ 2 ตัวกับรางเชื่อม 1 เส้น
- รางต้องไปทางขวาโดยรวม (x ปลายขวามากกว่าปลายซ้าย) ทำรางวนกลับหรือสามเหลี่ยมกลับรถไม่ได้
- สัญญาณอยู่ที่ปลายรางเท่านั้น ไม่มีเสาเตือน เสาเข้าเขตนอก หรือเสาออกอันนอก
- ขบวนยาว 72 เท่ากันทุกขบวน หยุดได้ทันที และกลับหัวได้เองทั้งขบวน (ไม่มีการสับเปลี่ยนหัวรถจักร ไม่มีการถอย)
- ขบวนที่ต้องจอดจะจอดที่ **ทางจอดเส้นแรกที่วิ่งถึง** จึงยังวางทางจอดสองเส้นต่อกันบนแนวเดียวไม่ได้
- ขบวนที่เข้าทางตันที่ไม่ใช่ทางจอดจะกลับหัวออกมาเองโดยไม่ได้คะแนนเข้าจอด
- ยังไม่มีห่วงทางสะดวกให้เห็น (M2) การขอและให้ทางสะดวกเป็นอัตโนมัติ, ยังไม่มีการหน่วงเวลายกเลิกเส้นทาง (M2), ไม่มีประแจกันชน
- ทางคู่: ยังไม่มีรางทางเดียวโดยกำเนิด ใช้ขา `dir: "in"` / `"out"` แทน (รางยังวิ่งได้สองทิศ แต่ไม่มีเสาและตารางขบวนให้วิ่งย้อน)

## ชุดด่าน (`data/levels/*.json`)

schema 2 (ชุดภารกิจบนแผนที่ ดู `docs/MISSIONS-NAMTOK.md` ข้อ 5 และตัวอย่าง `data/levels/test-crossing.json`):
```json
{
  "schema": 2, "id": "namtok", "kind": "career", "line": "west", "name_th": "เส้นทางสอน สายน้ำตก",
  "eras": [{ "name": "ขั้น 2 อินเตอร์ล็อกกล", "interlock": true, "sema": true, "tc": false, "nx": false }],
  "stations": [{ "station": "tha-kilen", "tier": 1, "needStars": 0 }],
  "levels": [{
    "id": "tk-1", "station": "tha-kilen", "era": 0, "name": "…", "teaches": "…", "goal": "…", "tips": ["…"],
    "speed": 48, "hints": true, "maxWait": 35, "waitGrace": 12, "pointsLocked": true,
    "trains": [
      { "at": 1, "from": "W", "to": "E", "track": "main" },
      { "after": { "train": 1, "event": "cleared", "delay": 3 }, "from": "E", "to": "W", "track": "loop1", "dwell": 6 },
      { "at": 30, "from": "W", "to": "E", "track": "main", "type": "express", "stop": false },
      { "at": 40, "from": "W", "to": "W", "track": "bay1", "dwell": 10 },
      { "at": 0, "origin": "loop1", "to": "E", "dwell": 5 }
    ]
  }]
}
```
- ยุค: `interlock` อินเตอร์ล็อก, `sema` วาดแขนสัญญาณ (ไม่ใช่ไฟสี), `tc` แสดงตอนรางที่มีรถ, `nx` ตั้งทางแบบต้นทาง–ปลายทาง; `lesson` ต้องมีในยุคที่ไม่มีอินเตอร์ล็อก (schema 1 ต้องมี `yr`, `story` ด้วย)
- `stations[]`: ลำดับสถานี = ลำดับปลดล็อก, `needStars` = ดาวสะสมขั้นต่ำ (ตัวตรวจตีกลับถ้าเกินดาวที่เก็บได้ก่อนถึงสถานีนั้น) ทุกด่านต้องอยู่ในสถานีที่ประกาศ
- `levels[].id`: คงที่ต่อภารกิจ ใช้เป็น key เซฟ (ห้ามซ้ำ ห้ามเปลี่ยน)
- `waitGrace`: วินาทีที่รอได้ก่อนเสียคะแนน เป็นเลขเดียว หรือ `{ "entry": รอเสาเข้า, "ready": พร้อมออก }` ไม่ใส่ = 6 / 4 แบบต้นแบบ
- `pointsLocked`: ประแจค้างท่าตรง แตะไม่ได้
- `holdGrace`: วินาทีที่สถานีข้างเคียงยอมกักขบวนรอ หลังขบวนข้างในพร้อมออก (ดูข้อ "สถานีข้างเคียงจะกักขบวน" ข้างล่าง) ไม่ใส่ = ช่วงผ่อนตอนพร้อมออกของด่าน + 10 วินาที, `null` = กักตลอด (ด่านนั้นจะไม่มีทางตันจากขบวนที่มาทับกัน)
- ตารางขบวน 1 แถว = 1 ขบวน **เลขขบวนที่ผู้เล่นเห็น = ลำดับในตาราง เริ่มที่ 1**
  - `at` วินาที หรือ `after: { train, event: "cleared", delay }` = มาหลังขบวนเลข `train` (ต้องอยู่ก่อนในตาราง) พ้นจอ `delay` วินาที
  - `from`, `to`: ชื่อขาใน `portals` (`from` = `to` คือเข้ามาจอดแล้วกลับหัวออกทางเดิม)
  - `track`: ชื่อบทบาทใน `roles` หรือเลขทาง ขบวนธรรมดาต้องมี ขบวนด่วนใส่ได้เพื่อบอกทางที่ควรผ่าน (ไม่บังคับ ไม่มีโทษถ้าผ่านทางอื่น)
  - `type`: `"local"` (ค่าเริ่มต้น) หรือ `"express"`; `stop: false` มีผลเท่ากับ express; `dwell`: วินาทีที่จอด (ค่าเริ่มต้น 2.5)
  - `origin`: ชื่อบทบาทหรือเลขทาง = ขบวนต้นทาง ตั้งอยู่ที่ทางจอดนั้นตั้งแต่เวลา `at` (ควรใช้ `at: 0`) ไม่ต้องมี `from` (ชื่อฟิลด์นี้เอนจินเพิ่มเอง ไม่อยู่ใน MISSIONS-NAMTOK)
- ขบวนจากขาที่มีตอนทางเดี่ยว: สถานีข้างเคียงขอทางล่วงหน้า `runTime` วินาที ถ้าตอนไม่ว่างขบวนถูกกักไว้ แล้วโผล่หลังตอนว่าง `runTime` วินาที (ไม่คิดโทษเวลารอช่วงนี้) ขบวน `after` ที่มาจากขาเดียวกับที่ขบวนก่อนเพิ่งออกไปจึงมาช้ากว่า `delay`
- สถานีข้างเคียงจะกักขบวนไว้ก่อน (ไม่คิดโทษ) ถ้าทุกทางที่ขบวนนั้นเข้าได้ มีขบวนที่ต้องออกไปทางขาเดียวกันกำลังเข้า จอดรับผู้โดยสาร หรือพร้อมออกแล้วรอยังไม่เกิน `holdGrace` เพราะถ้าส่งมาจะเป็นทางตันที่ผู้เล่นแก้ไม่ได้ ถ้าผู้เล่นปล่อยช้าเกินช่วงนั้น ขบวนใหม่มาตามปกติและอาจเกิดทางตัน
- ทางตัน (`DEADLOCK`, ทุกยุค เฉพาะผัง schema 2; ยุคไม่มีอินเตอร์ล็อกขึ้นหัวข้อ "ติดขัด!"): ทุกขบวนหยุดนิ่งหน้าเสาที่ห้ามครบ 3 วินาที และไม่มีเส้นทางใดที่ทั้งตั้งได้และพาขบวนไปถึงขาออกของตัวเอง (เส้นทางออกผิดขาไม่นับ) ถ้ายังมีทางสำรอง เช่น รับเข้าทางจอดอื่น เกมไม่ตัดสินแพ้ แต่คำใบ้จะชี้ทางนั้น ถ้านิ่งเกิน 45 วินาทีโดยยังไม่เข้าเงื่อนไขทางตัน (เช่น เปิดเส้นทางค้างไว้) เอนจินส่ง event `stall` ให้หน้าจอขึ้นคำใบ้หรือปุ่มเริ่มใหม่ ไม่ตัดสินแพ้ ตอนออกแบบตารางขบวนให้ระวังขาที่เข้าได้ทางจอดเดียว (เช่น ขา C ของหนองปลาดุกเข้าได้เฉพาะ `t3`)
- ตัวตรวจปิดเฉพาะด่านที่อ้างขา บทบาททาง หรือเส้นทางที่ผังไม่มี (`lv.error` บอกเหตุผล) ด่านอื่นยังเล่นได้
- รูปแบบเดิมยังใช้ได้ทุก schema: `{ "pattern": "12E21", "gap": 9, "start": 1 }` (เลข = เลขทาง, `E` = ด่วน) หรือ `[[วินาที, เลขทาง, "ขอบขาเข้า"], …]` เข้าทางขาแรก ออกขาไหนก็ได้

## ภาคผนวก: schema 1 (ผังทิศเดียวของโหมดประวัติศาสตร์ ห้ามใช้กับสถานีจริง)
```json
{
  "schema": 1,
  "id": "fictional-history-2-platforms",
  "fictional": true,
  "name_th": "…", "name_en": "…",
  "verified": { "layout": false, "signalling": false, "notes": "" },
  "sources": [],
  "layout": {
    "size": [960, 480],
    "edges": {
      "in":  { "pts": [[-100, 300], [150, 300]], "dir": "E", "sig": "S1", "next": "ap" },
      "ap":  { "pts": [[150, 300], [190, 300]], "dir": "E", "next": { "pt": "P1", "N": "c", "R": "b" } },
      "x1":  { "pts": [[640, 210], [740, 210], [810, 300]], "dir": "E", "next": { "trail": "P2", "as": "R", "to": "out" } },
      "p1":  { "pts": [[360, 210], [640, 210]], "dir": "E", "sig": "T1", "plat": 1, "next": "x1" },
      "out": { "pts": [[810, 300], [1070, 300]], "dir": "E", "exit": true }
    },
    "points":  { "P1": { "x": 190, "y": 300, "N": "c", "R": "b", "facing": true } },
    "signals": { "S1": { "edge": "in", "lx": 132, "ly": 256, "dir": "E", "type": "home" } },
    "platforms": [{ "edge": "p1", "no": 1 }],
    "entries": ["in"],
    "exits": ["out"]
  }
}
```

| ฟิลด์ | ความหมาย |
|---|---|
| `schema` | `1` |
| `fictional` | `true` = ผังสมมุติ, `false` = อ้างอิงสถานีจริง |
| `verified.layout` / `verified.signalling` | ผ่านการตรวจผัง / มีแหล่งสาธารณะยืนยันระบบสัญญาณ (ความหมายตาม `docs/DATA-PIPELINE.md` ข้อ 4) |
| `sources` | รายการแหล่งอ้างอิง เช่น `{ "osm": "https://www.openstreetmap.org/node/…", "fetched": "2026-10-12" }` (ผังสมมุติใส่ `[]`) |
| `layout.size` | ขนาดแผง `[กว้าง, สูง]` ไม่ใส่ = `[960, 480]` |

#### `layout.edges` ขอบราง (มีทิศ)
- `pts`: polyline อย่างน้อย 2 จุด **ขบวนวิ่งจากจุดแรกไปจุดสุดท้ายเท่านั้น** ขอบราง 1 เส้น = ราง 1 ท่อนใน 1 ทิศ
- `dir`: ทิศที่ขอบนี้พาขบวนไป `"E"` (ไปทางขวาของแผง) หรือ `"W"` ไม่ใส่ = `"E"`
- `next`: ขอบถัดไป มี 3 แบบ
  - `"ชื่อขอบ"` ต่อตรง
  - `{ "pt": "P1", "N": "c", "R": "b" }` ประแจสวน (facing): รถไปทาง N หรือ R ตามที่ประแจตั้ง
  - `{ "trail": "P2", "as": "R", "to": "out" }` ประแจตาม (trailing): รถมาจากขา `as` ถ้าประแจไม่ได้ตั้งขานี้ รถตกราง
- `exit: true`: ขอบขาออก รถวิ่งสุดขอบแล้วออกจากผัง (ต้องไม่มี `next` และต้องอยู่ใน `layout.exits`)
- `sig`, `plat`: ใส่ซ้ำกับ `signals` / `platforms` ได้เพื่อให้อ่านง่าย (รูปแบบเดียวกับต้นแบบ v2) ถ้าใส่ต้องตรงกัน

#### `layout.points` ประแจ
`x`, `y` ตำแหน่ง, `N` / `R` ขอบของทางตรง / ทางแยก, `facing` `true` = ประแจสวน `false` = ประแจตาม ต้องตรงกับ `next` ของขอบที่อ้างถึง

#### `layout.signals` สัญญาณ
- `edge`: สัญญาณตั้งอยู่ **ปลายขอบนี้** และบังคับขบวนที่วิ่งบนขอบนี้ (ขอบละไม่เกิน 1 ต้น)
- `dir`: ทิศของขบวนที่สัญญาณนี้บังคับ ต้องตรงกับ `dir` ของขอบ ไม่ใส่ = ตามขอบ
- `type`: `"home"` (สัญญาณเข้า), `"starter"` (สัญญาณออก) ตอนนี้ตัวจำลองยังไม่ใช้ เก็บไว้ให้ตัววาดและขั้นถัดไป
- `lx`, `ly`: ตำแหน่งเสาบนแผง

#### `layout.platforms`, `entries`, `exits`
- `platforms`: `{ "edge", "no" }` ขอบชานชาลาต้องมีสัญญาณออกที่ปลาย
- `entries`: ขอบที่ขบวนเกิดได้ (หลายฝั่งได้ ตารางขบวนเลือกได้ว่าเข้าทางไหน ไม่ระบุ = ตัวแรก)
- `exits`: ขอบขาออกทั้งหมด

## สิ่งที่เกมคำนวณเอง (ไม่ต้องเขียนในไฟล์)
- ความยาวขอบ และตารางเส้นทางของสัญญาณแต่ละต้น (ไปถึงไหนได้ ต้องตั้งประแจอะไร) คำนวณจากกราฟ ดู `routes` และ `REQ` ใน `src/sim/station.js`
- ตัวตรวจยังดู: ขอบที่อ้างถึงมีจริง, ประแจกับขอบตรงกัน, ไม่มีรางวนเป็นวง, ทุกขอบไปถึงได้จากขาเข้า, ทุกขาเข้าไปถึงขาออกได้
